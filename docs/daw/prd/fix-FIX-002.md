# Fix FIX-002: Subir el timeout de arranque de mongod en los tests de integración

- **Bug**: los tests de integración que usan `mongodb-memory-server` fallan con `GenericMMSError: Instance failed to start within 10000ms` en esta máquina — `mongod.exe` tarda más de los 10000 ms que la librería da por defecto (`MongoInstance.js`, fallback hardcodeado `1000 * 10` cuando no se pasa `instanceOpts.launchTimeout`). Reproducido de forma estable en 3 intentos consecutivos, incluso con el binario de Mongo ya descargado y cacheado (no es un problema de red/descarga).
- **Change**: `backend/src/__tests__/helpers/testDatabase.ts` — pasar `{ instance: { launchTimeout: 30000 } }` a `MongoMemoryServer.create()` en `startTestDatabase()`, para darle a `mongod` más margen de arranque en máquinas lentas sin afectar el comportamiento en máquinas rápidas (el timeout solo se usa si el arranque lo necesita).
- **Regression test**: no aplica un test nuevo — el fix se valida con la suite de integración existente (`src/__tests__/integration/**`), que hoy falla por este timeout y debe pasar en verde después del cambio. Se documenta la corrida antes/después en el reporte de `daw-test`.
- **Risk**: bajo — el cambio es exclusivo de la configuración de tests (`testDatabase.ts`), no toca código de producción. Un timeout más alto solo alarga cuánto espera un test antes de fallar si `mongod` realmente no arranca; no cambia ningún comportamiento funcional.
